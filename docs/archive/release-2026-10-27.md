Core structure, outbound request-length measurement, the optional two-flake
reactor and persistent material simulation are integrated in main. The owner’s
presentation workstream produced proposals only. All verification is local;
GitHub is repository storage only, with automatic workflow triggers disabled.

## What changed

- Task Plan revisions and progress are written atomically. Modern model-driven
  Hands work declares sample completion conditions; a successful but wrong
  physical operation cannot satisfy a different destination or sample state.
- Role/tool boundaries, bounded experience retrieval, instrument observations,
  target-derived flake dimensions and the three-column Lab navigation follow
  the confirmed core review. Progress groups each job under its originating
  tool. Old recordings remain readable.
- Each actual outbound model HTTP attempt records its text length and agent.
  History → Context shows the complete recording; Results → Request lengths
  follows the replay position. Counts are Unicode characters, **not tokens**;
  they do not enforce or certify a Qwen context limit.
- New simulated flakes retain geometry and provenance across magnification,
  observation and transfer. New observations use an independent random stream.
  The cluster/contact morphology profile is explicit and opt-in.
- The optional reactor processes exactly two prepared small flakes and accepts
  at most one product inside their overlap. Source IDs remain as consumed
  history. Acceptance is transactional, persisted restart is checked, and lost
  observation parks the reaction without inventing a product.
- Reactor Results show the saved acceptance image, source flakes, preparation
  and evidence job. Documentation distinguishes current contracts from archived
  prototypes. Normal and reactor workspaces use the same launcher and separate
  saved databases.

## Findings from acceptance

Live runs exposed and helped correct an unnecessary post-search storage action,
completion without checking the intended sample state, ambiguous pose units,
and a mistaken mandatory backup-flake requirement. Shortage reports now require
structured optical evidence when readable candidate count is already sufficient.
Enough assessed feasible candidates cannot justify consuming more chips merely
for an optional backup; genuine optical rejection still can.

An additional new device-approval attempt did **not** pass. It first stopped at
its budget boundary, then continued in the same saved run and spend scope. After
selecting one suitable flake, it stopped because the layout checker still applied
a generic 5 × 10 µm rule instead of the resolved 33 × 4 µm target footprint.
That inconsistency is fixed with regression coverage, and scripted layouts now
follow the same resolved requirement. The failed live attempt remains private;
it was not reset, rewritten as success or promoted. No fresh successful live
device-approval recording is claimed. The 25 October version is clearly historical.

## Limits and next decisions

The reactor inputs are preprepared synthetic pairs. These recordings do not
demonstrate autonomous exfoliation, selection and stacking into a reactor pair.
Material dynamics remain qualitative and uncalibrated: no chemical identity,
reaction yield, product thickness or electrical performance is established.
The layout check still uses simple rectangles; KLayout integration is deferred.
No physical hardware was operated.

Presentation proposals remain unimplemented: short story chapters; clearer
human instruction → plan change → agent result; a failure/correction/recheck
sequence; selective apparatus close-ups; and separate apparatus/flake scales.
The next useful step is to choose the presentation story and rehearse it before
adding visual effects. The owner’s proposal note is in the local project notes.
