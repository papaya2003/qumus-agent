## Structure review

The repository retains one application runtime, ToolGateway, SafetyGate, job
scheduler and laboratory event store. The normal launcher remains
`../Start Qumus.command`. No alternate review application, settings store or
laboratory recovery database was introduced.

The added or relocated modules have distinct responsibilities:

- `core/polygons.py` relocates the existing pure polygon calculations out of the
  simulator so records and execution can share them. The old duplicate location
  is removed and callers use the common module.
- `flows/library/pickup_evidence.py` captures neighbourhood evidence. Pure
  validity and containment rules stay in `records/geometry.py`; records do not
  depend on flow orchestration.
- `flows/library/stage_cooling.py` implements final cooling as normal checked
  Steps, with existing locks, events, Clock and restart handling.
- `records/experiment_completion.py` centralizes existing completion predicates
  for tool and lab-process callers instead of maintaining two competing checks.
- `scripts/record_three_demos.py` wraps the existing runtime/recorder. A small
  private registry tracks attempts of three stories without erasing failures. All laboratory
  state, scripted effects and usage evidence remain in RunStore; SpendLedger
  remains the sole spending ledger.

Material-metal work uses the common model-visible `stack_device` tool and shared
transfer mechanics. Its existing preparation job composition retains the contextual
carrier handover and experiment receipt. Compatibility queries/tools are bounded
and kept out of the model-visible surface where appropriate. Frozen v1 and
historical recordings are preserved rather than silently migrated.

The architecture document was reorganized around current responsibilities and
C1–C13 contracts, replacing accumulated dated sections and duplicated descriptions.
Its word count was reduced by about a quarter. Current workstreams, contract
explanations and release evidence have separate purposes; no broad unrelated
refactor or dependency migration was added to reduce line counts.

## Review findings resolved before acceptance

| Finding | Required corrected behavior |
| --- | --- |
| Nominal zero-transform coverage ignored real placement | Before pickup contact, compare current stamp/source camera-plane outlines, including observed rotation and offsets |
| Reused source evidence survived changed samples | Reject old evidence after new exfoliation, source removal/reset/material change or flake relocation; retain original provenance |
| Failed shutdown could release output locks | Confirm off targets through trusted interfaces, retain failed locks and preserve the fault marker through worker error handling |
| Reverify or restart could bypass the shutdown fault | Verify shutdown only; never mark the original process Step successful or restore heat while the fault remains |
| Recovery at a camera/motion Step missed earlier heating | Check the entire Flow shutdown scope before releasing its locks, while keeping read-only verification non-mutating |
| Stop failed before shutdown when target readback threw | Attempt all relevant off commands despite unreadable saved targets; unconfirmed feedback retains locks |
| New abnormal-exit shutdown lost normal heating recovery | Preserve readable targets in existing metadata and use the checked resume path; reject unsafe restoration and keep final cooling non-reheating |
| Diagnostic selection chose a barely fitting first pair | Rank already observed valid combinations by coverage clearance; retain ordinary noise and strict execution checks |
| Additive metal-image fixture changed an old checkpoint's layout hash | Accept only its exact pre-field signature with matching mechanics and reactor devices; preserve physical state and reject all other layout changes |
| A valid `graphene` request was compared with canonical `Gr` evidence | Reuse material normalization before checking and saving requirements; preserve the person's original request and reject absent materials |
| Exfoliation produced a receiving chip but a model-written plan bound its status to the source carrier | Reject new role mismatches; repair unsubmitted status mistakes without changing the source, or repair submitted identity mistakes only from the exact successful job and storage evidence; recheck that original job before completion |

These findings were reproduced locally. Positive PC/mica preparation and legal
crash recovery are required alongside rejection tests: merely stopping all
